# Ask the Sensors

**Grounded, explainable activity question answering from wearable signals**
CS60055 Ubiquitous Computing, IIT Kharagpur — Hackathon Challenge 1

Given a raw accelerometer + gyroscope recording and a natural-language question, the system
returns a structured answer about the user's activity and grounds it in the specific stretch
of signal that supports it (timestamps, modality, channels, and a signal-based explanation).

## Approach

A four-layer pipeline. Every answer the last layer produces is computed from, and cites,
evidence found by the earlier layers; no activity claim is generated by language reasoning alone.

```
recording (acc + gyro) ──► preprocess ──► recognize ──► aggregate ──► query ──► answer + evidence
                           resample     per-window     intervals,    intent →
                           to 25 Hz,    7-class        durations,    operation
                           window       classifier     counts,       over timeline,
                                                       transitions   formatted output
```

1. **Preprocess** (`src/preprocess/`): resample streams to 25 Hz, handle gaps, cut into
   fixed windows with start/end timestamps.
2. **Recognize** (`src/recognize/`): per-window features (time- and frequency-domain over
   Acc X/Y/Z, Gyro X/Y/Z, and magnitudes) → light classifier over the seven classes:
   lying down, sitting, standing in place, standing and moving, walking, running, bicycling.
3. **Aggregate** (`src/aggregate/`): smooth window predictions, merge into activity intervals
   with per-interval signal statistics, derive durations, counts, onsets, and comparisons.
4. **Query** (`src/query/`): map a question to an intent (identify, verify, duration, count,
   when, compare, open-world), run it over the interval timeline, and emit the required
   output format. A small language model may assist with parsing and phrasing, but only
   over the structured evidence it is handed.

Time convention: all timestamps are reported as **seconds from the start of the recording**.

## Data

We use the [ExtraSensory dataset](http://extrasensory.ucsd.edu/) (Vaizman, Ellis, Lanckriet,
IEEE Pervasive Computing 2017). Only the phone accelerometer and calibrated gyroscope are used.
Both are recorded at 40 Hz in ~20 s bursts, one per labelled minute, and are resampled to 25 Hz.

Labels: the cleaned labels give lying down, sitting, walking, running, and bicycling; the two
standing classes come from the original (uncleaned) labels, since the cleaned set merges them
into `OR_standing`. Where a minute carries more than one of the seven labels, the most dynamic
activity is kept. Train/test splits follow the dataset's official 5-fold user-level partition
(the fold files are split by phone OS; we concatenate the Android and iPhone halves).

### In-the-wild data issues we handle explicitly

- **Jittery accelerometer clock.** Phone accelerometer bursts are nominally 40 Hz for 20 s but
  often span 22-24 s for the same 800 samples; the gyroscope is a clean 40 Hz. Both are
  interpolated onto a 25 Hz grid using their real timestamps and trimmed to a common length.
- **Corrupted timestamps.** Some bursts have non-monotonic time columns (clock adjustments
  mid-recording) and at least one gyroscope burst has a zeroed timestamp giving an apparent
  span of 1.44e9 s, which hangs naive resampling. Every burst's time base is validated (finite,
  strictly increasing, <= 60 s); on failure we fall back to the nominal 40 Hz grid.
- **Class imbalance.** Sedentary classes are ~85% of labelled minutes. At feature-extraction
  time we cap lying down, sitting, and standing-and-moving at 400 minutes per user (random,
  seed 0) and keep every minute of the other four classes. Running remains the rarest class
  (~1% of windows). The cap is a deliberate design choice and is reported as such.
- **Scale.** ~600k raw burst files, per-user counts varying 4x. Extraction indexes each user
  directory once (not once per minute), is vectorised across channels, and caches one file per
  user so it can be resumed.

The raw dataset is **not** committed. Fetch it with:

```bash
python scripts/prepare_data.py                    # labels, original labels, CV folds (~220 MB)
python scripts/prepare_data.py --raw --only acc   # phone accelerometer  (6.1 GB)
python scripts/prepare_data.py --raw --only gyro  # calibrated gyroscope (8.7 GB)
```

Downloads resume if interrupted. The dataset site asks for one large file at a time.
Everything lands under `data/`, which is git-ignored.

## Recognition layer

Each 20 s burst is cut into 5 s windows with a 2.5 s hop (7 per minute). For each window we
compute, over 8 signals (Acc X/Y/Z, Gyro X/Y/Z, |Acc|, |Gyro|), 12 time-domain statistics
(mean, std, min, max, range, median, IQR, RMS, skew, kurtosis, zero-crossing rate, MAD) and
9 frequency-domain features (dominant frequency and its power, spectral entropy and centroid,
power in five bands from 0 to 12.5 Hz), plus 7 cross-axis correlations: 175 features, every
one named so the explanation layer can cite real computed values. Windows inherit the minute's
label for training; at inference window probabilities are averaged per minute.

The backbone is a class-weighted tree ensemble (Random Forest; HistGradientBoosting as the
comparison model), evaluated leave-users-out with the official folds at minute granularity.
